# Протокол безопасной публикации бота

Этот протокол обязателен для любого изменения — даже если меняется одна
формулировка, одна кнопка или только картинка. Его цель: не исправлять одну
часть бота ценой поломки остальных.

## До изменения

1. Сформулировать, какой пользовательский сценарий сломан, и воспроизвести его.
2. Найти обработчик кнопки, текст и резервный путь при сетевой ошибке.
3. Не менять секреты, токены, пользовательские данные и чужие незакоммиченные
   изменения без отдельного разрешения.

## Перед публикацией

Из корня репозитория выполнить все проверки. Они должны завершиться без ошибок:

```bash
PYTHONPATH=. python3 tests/audit_bot_runtime.py
PYTHONPATH=. python3 tests/test_oracle_delivery.py
PYTHONPATH=. python3 tests/test_button_fallbacks.py
PYTHONPATH=. python3 tests/test_railway_singleton.py
```

Проверки означают следующее:

- 64 карты и все 384 трактовки линий существуют, не обрываются, не повторяют
  друг друга и не выводят техническую терминологию;
- послание Оракула помещается в подпись к изображению, приходит вместе с картой,
  а шесть кнопок находятся после текста;
- каждое главное действие имеет обработчик, а все личные залы и прогнозы
  вызывают собственную методологию, получают обезличенные расчётные факты и
  возвращают законченный текст с абзацами; общий резервный текст запрещён;
- дата, время и место рождения распознаются одним сообщением;
- политика обработки данных открывается до ввода рождения, её принятие
  подтверждается отдельной кнопкой, а имя и ник не собираются для расчёта;
- тест двух независимых сессий подтверждает, что в ответ не попадают имя,
  дата рождения или игровой псевдоним другого пользователя;
- только Railway-проект `hearty-stillness` имеет право запускать Telegram
  long polling.

## Неприкосновенность методологии

Запрещено публиковать изменение, если хотя бы одна личная кнопка:

- не использует свой блок из `BLOCK_PROMPTS`;
- не получает заново рассчитанный бодиграф и астрологическую карту;
- заменяет ошибку провайдера универсальной интерпретацией;
- отправляет провайдеру имя, Telegram ID, дату, время, место или координаты
  рождения вместо обезличенных производных фактов;
- возвращает меньше четырёх законченных абзацев или технический жаргон.

Обработчик кнопки обязан сам дождаться `deliver_block_reading(...)` и отправить
полный результат либо явную ошибку. И `asyncio.create_task(...)`, и
`Application.create_task(...)` для персонального разбора запрещены: после
выноса расчёта в фон Telegram показывал «Собираю…», а продолжение терялось.

Railway-процесс без подтверждённого `RAILWAY_PROJECT_ID` не имеет права
начинать long polling.

Астрологический расчёт выполняется локальным `server.py` через Swiss
Ephemeris; бодиграф рассчитывается отдельным инструментом `human_design` на
тех же исходных данных. ИИ не пересчитывает карту, а только переводит готовые
факты в текст по методологии выбранной кнопки.

## После публикации

1. Убедиться, что GitHub получил нужный коммит.
2. Дождаться статуса Railway `Deployment successful` именно для этого коммита.
3. Пройти живой сценарий в Telegram: `/start` → Оракул → вопрос → карта с
   посланием → линия 1–6 → личная карта → каждый пункт Олимпа → прогноз.
4. Только после этого говорить, что исправление работает в production. Если
   нет доступа к живой проверке, прямо обозначить это как непроверенный шаг.
